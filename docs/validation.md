# Validation results

Measured on 18 October 2026. These results describe the checked fixtures and hosts, not universal accuracy or performance guarantees. The timings and counts below are dated, host- and fixture-coupled snapshots; regenerate them with `scripts/benchmark.py`, `scripts/scale_benchmark.py`, `scripts/accuracy.py`, and `blastradius scan --path examples/demo`. None of them are enforced as CI gates.

## Automated checks

The suite covers deterministic output, read-only scans, ignore rules, parser failures, resolver configurations, JS grammar, shadowed CommonJS imports, coverage accounting, cycles, deep paths, comparison uncertainty, database transactions, and the harness API.

Local Windows result: **84 passed, 6 skipped**. The count is host-dependent: on a host that forbids symlink creation, the two symlink tests (`tests/test_discovery.py`, `tests/test_harness.py`) skip as well, giving **82 passed, 8 skipped**. The six database skips are PostgreSQL integration tests; they run in the database CI job. The installed Starlette version emits a deprecation warning for its current httpx TestClient adapter; it does not fail the tests.

CI runs nine OS/Python combinations: Windows, Linux, and macOS with Python 3.11, 3.12, and 3.13. Each job runs lint, tests, the accuracy corpus, a zero-finding self-scan, builds, wheel-content checks, and a clean wheel installation. A tenth job runs against PostgreSQL 17, including actual save/load/rollback and CLI/harness comparison flows. Database tests skip locally when `BLASTRADIUS_TEST_DATABASE_URL` is absent. Follow [GitHub Actions](https://github.com/Taarunkarthik/BLAST_RADIUS/actions) for per-commit results.

Target: zero unexpected or missed diagnostic identities in this reviewed finite corpus. These per-case counts are a dated, fixture-coupled snapshot regenerated by `python scripts/accuracy.py`; they are not enforced as a CI gate. This is a regression gate, not a statistically representative measurement across all repositories. Expected identities include file, issue type, and target; line and severity behavior has separate unit tests.

The resolver regression suite also covers nearest workspace manifests, hoisted dependencies, package imports, JavaScript containing forbidden TypeScript syntax, and parameter/block/function/catch/destructuring/loop bindings named `require`.

## Performance and bounds

On the development Windows host, `python scripts/benchmark.py --files 1000` completed in **4.769 seconds** after the accuracy changes. This temporary repository has 999 dependents of one failing module. It meets the PRD's five-second target for this case; cold caches, slower hosts, different project layouts, and complex configurations can take longer.

`python scripts/scale_benchmark.py` measured graph construction plus one impact traversal with Python allocation tracking:

| Shape | Nodes | Edges | Seconds | Peak traced Python allocation |
| --- | ---: | ---: | ---: | ---: |
| Deep chain | 2,000 | 1,999 | 1.370 | 17.02 MiB |
| Dense cycle | 300 | 89,700 | 2.424 | 37.82 MiB |
| Wide star | 10,000 | 9,999 | 0.853 | 6.23 MiB |

These are graph timings, not full scans; allocation peaks are not whole-process RSS and exclude Node. Automated tests additionally verify a 5,002-file repository stopped at the 5,000-file cap, exact coverage partitioning, deep paths without recursive traversal, and dense cycles without duplicate affected counts. Timing thresholds are not enforced in CI.

## Browser verification

The local demo was exercised through the browser: full and health scans, severity and search filters, finding selection, direct/transitive impact, No Tree Impact, coverage, and the unconfigured saved-history state. The demo shows five findings, nine checked files, one unsupported SVG, and three unique affected JS/TS files in full mode. These demo counts are a dated snapshot regenerated with `blastradius scan --path examples/demo`; they are not enforced as a CI gate. Automated HTTP tests cover loopback/host/origin/session guards, scan boundaries, body limits, concurrent scans, stale report IDs, and read-only behavior. The PostgreSQL CI job verifies the harness save/history/compare API against a real database; the development machine does not have a running PostgreSQL service.

## Scope boundaries

The checks do not establish semantic type correctness, runtime correctness, CSS value validity, remote-link health, HTML/Markdown fragment existence, custom Sass load paths, or nested JSON Schema `$id` behavior. Python/Go/Rust analyzers and remediation are future scope. See [the tracked phases](PHASES.md).
